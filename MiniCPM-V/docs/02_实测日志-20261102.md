## 二、速度（60 次调用的结论）

| 阶段 | 耗时 | 占比 |
|---|---|---|
| load（冷启） | 6–7 s | 只在第一次 |
| **prefill（看图）** | **6.14 s** | **93%** |
| decode（写字） | 0.18 s | 3% |
| **单次总计** | **6.0–6.5 s** | |

- 视觉 token：1706×1279 → **701 tok**；1000 宽 → 375；700 宽 → 258；480 宽 → 114
- prefill 吞吐 ≈ **125 tok/s**，decode ≈ **82–110 tok/s**
- 显存 2181 MiB，`ollama ps` = **100% GPU**，上下文 8192

**结论：慢的不是"思考"，是"看图"。** 生成 18 个字只要 0.18 s。

## 三、今天踩的三个坑（都会误导判断）

### 坑 1：`ollama run` 用相对路径会**静默丢图**

```powershell
ollama run ... "描述" .\a.jpg          # ✗ 图被丢掉，不报错
ollama run ... "描述" "a.jpg"          # ✗ 同上
ollama run ... "描述" "D:\path\a.jpg"  # ✓ 会打印 "Added image '...'"
```

丢了图之后，模型会**拿文件名编故事**（"这是一幅像素化图形，核心是数字编码 5a453eda…"）。
👉 **判断标准**：CLI 回显里没有 `Added image` = 图没进去。
👉 **正式做法**：走 API，`images` 字段显式传 base64。

### 坑 2："第二次变快"是缓存，不是真快

同一张图 + 同一个问题，第二次起 prefill 从 6.1 s 掉到 **0.03 s**（总耗时 0.36 s）。
把问题改一个字，立刻回到 6.1 s。

👉 **测性能时绝不能重复跑同一条**，否则测的是缓存。

### 坑 3：缩图能快 7 倍，但会**把目标缩没**

| 输入宽度 | 视觉 token | prefill | test2 红点（原 53 px）剩多少 | 模型回答 |
|---|---|---|---|---|
| 1706 | 701 | 5.8 s | 53 px | "有…白板纸张上"（但也会说"没有"） |
| 700 | 258 | 2.1 s | **22 px** | **"没有红色圆点"** ❌ |
| 480 | 114 | 0.72 s | **15 px** | **"没有红色圆点"** ❌ |

👉 省时间 = 丢细节。**对我们这种任务是致命的，不能缩。**

## 五、稳定性（最重要的发现）

同一张办公室图、同一个问题"有没有红色圆点"：

| 次数 | 回答 |
|---|---|
| 用户第 1 次 | "**有**，一个红色圆点位于白板上的纸张上，画面中央偏右" ✅ |
| 后续 3 次（同参数） | "**没有**，但有一个红色圆点，它位于白板上的一个红色圆形标记" ⚠️ 自相矛盾 |
| 缩到 700 / 480 | "**没有红色圆点**" ❌ |

👉 **同一个输入会给出互相矛盾的答案。** 这是比"慢"严重得多的问题：
一个时而说"有"时而说"没有"的模型，不能进任何决策链。

**下一步必须量化它**：同一张图问 N 次，统计"有/没有"各几次。

## 七、红点实验（8 张图，两种问法）

### 素材

| 文件 | 内容 | 真值 |
|---|---|---|
| test1.jpg | 园林古塔（前景灌木有红色嫩叶） | **无**红点 |
| test2.jpg | 办公室全景（白板纸上红点 53 px） | **有** |
| test3.jpg | 白板特写（红点 110 px） | **有** |
| neg1 | 白墙 | 无 |
| neg2 | 桌面（鼠标有红色指示灯） | 无 |
| neg3 | **夜景窗外楼宇**（最接近真实场景） | 无 |
| neg4 | 楼梯 | 无 |
| neg5 | 天花板 + 红色消防管 | 无 |

> neg2/neg3/neg5 里都有红色物体，是很好的"难负样本"。

### 问法 A：带"没有"的出口

> "……如果有，指出位置；**如果没有，请直接回答"没有"。**"

结果：**8 张全部以"没有"开头**，包括 2 张真有红点的：

| 图 | 回答 |
|---|---|
| test2 | "没有，**但有一个红色圆点**，它位于白板上的一个红色圆形标记" |
| test3 | "没有。位置：白色白板右侧贴有红色圆点。" |

👉 **模型被"没有"这个词锚住了**：先套答案，再补内容，自相矛盾。
👉 按"有没有"判：**漏报 2/2，召回率 0%**。

### 问法 B：强制单字

> "仔细看这张图。图中有没有红色圆点？**只回答一个字：有 或 无。**"

| 图 | 真值 | 回答 | 判 |
|---|---|---|---|
| neg1–neg5 | 无 | 无 无 无 无 无 | ✅ 5/5 |
| test1 | 无 | **有** | ❌ 误报 |
| test2 | 有 | 有 | ✅ |
| test3 | 有 | 有 | ✅ |

- 负样本 6 张（neg1–5 + test1），误报 **1** ⇒ **假阳性率 ≈ 17%**
- 正样本 2 张，全中 ⇒ 召回 2/2（但 **n=2，不足以下结论**）

### 稳定性（temperature=0.7，各 6 次）

| 图 | 6 次结果 |
|---|---|
| test1 | 有 有 有 有 有 有 |
| test2 | 有 有 有 有 有 有 |
| neg3 | 无 无 无 无 无 无 |

👉 **单字问法下模型是稳定的**。之前的"有/没有"乱跳，**不是随机，是问法造成的**。

### test1 为什么误报？——CV 扫出来的答案

用 R−max(G,B)>40 扫 test1，**红色块 109 个**（最大 71 px，是前景灌木的红色嫩叶）。

👉 所以它**不是纯瞎编**，是"背景里真有一堆红色小块"。
👉 这正好说明：**在真实建筑场景（红叶、红砖、红招牌、尾灯）里，问"有没有红色圆点"必然被干扰。**
👉 该问的是**上下文**："它是不是贴在玻璃上的标记？" 而不是"它是不是红色圆形？"

### 本节结论

1. **问法比模型重要**：同一个模型，A 漏报 100%，B 误报 17%。
2. 单字强制问法下模型**稳定**（temp 0.7 ×6 完全一致）。
3. 误报来自**背景红色干扰**，不是随机幻觉 ⇒ 需要上下文判断，不是颜色判断。
4. 报告里必须写明"用什么问法"，否则指标无法复现。

## 八、第二轮：问法矩阵 + 假阳性控制

### 8.1 四种问法对比（8 张整图）

| 问法 | 准确率 | 备注 |
|---|---|---|
| P1「有没有红色圆点？只回答 有/无」 | 7/8 | test1 误报 |
| P2「有没有**贴在窗玻璃或白纸上的**红色圆形标记？」 | 8/8 | |
| P3「A：有标记 / B：没有标记，只回答 A 或 B」 | **8/8** | 对称选项 |
| P4「可能性多大？输出 0–100 整数」 | 6/8 | **只会吐 0 / 5 / 10** |

**P4 的结论**：1B 模型给不了可用置信度。⇒ 概率/校准这件事必须交给 Jev/Laya。

### 8.2 采样参数（回答"官方那套是不是最优"）

| 配置 | 结果 |
|---|---|
| 贪心 `temperature=0` | 8/8 |
| 官方 `temp0.7/top_p0.95/top_k100/min_p0/repeat1.03`，3 次取多数 | 8/8（3 次全同一个字母） |

**官方参数是给"生成自然语言"的，分类任务用贪心**：确定、快 3 倍、好复现。

### 8.3 ★ 但 8/8 是假象——涂掉对照实验

把红点从图上**涂掉**再问：

| 图 | 原图 | 涂掉红点后 |
|---|---|---|
| test3 | 有 | **有** ❌ |
| test3（连纸带点整块涂掉） | 有 | **有** ❌ |
| test2 | 有 | **有** ❌ |

涂掉还说"有"。问它"图里有哪些红色物体"，它答：**"红色管道……"**

⇒ **它答的是"画面里有没有红色物体"，不是"有没有那个标记"。**
test3 有蜘蛛侠贴纸、彩旗环；test2 有红色消防管 —— 随便哪个都能触发。
**整图提问的 8/8 不能算数。**

### 8.4 裁剪之后才有效

裁到只剩红点那一小块（190×190 放大 3 倍）：

| 输入 | 红像素 | 回答 |
|---|---|---|
| 紧裁（有红点） | 13130 | 是 ✓ |
| 同一块，红点全涂掉 | **0** | **不是** ✓ |
| 紧裁（只有字迹） | 450 | 是 ✗ |

⇒ 裁剪尺度下它**真的在看那个点**。这就是"CV 找候选 → 裁剪 → VLM 判局部"的动力。

### 8.5 干净的距离阶梯（今天最硬的数）

白墙（本身无红）+ 贴一个直径 d 的红点，1920×1080：

| 红点 | 等效距离（20 cm 标记, f=1579） | 回答 |
|---|---|---|
| 110 px | 3 m | 有 |
| 55 px | 6 m | 有 |
| 28 px | 11 m | 有 |
| 14 px | 23 m | 有 |
| **7 px** | **45 m** | **有** |
| **4 px** | **79 m** | **无** |
| 3 px | 105 m | 无 |
| 0（对照） | — | 无 ✓ |

**检出下限在 4–7 px 之间：45 m 能认、79 m 认不出、100 m 明确不行。**
（原估"14 px = 1 patch ⇒ 22.6 m"太保守，实测 7 px 就够。）

### 8.6 官方 grounding 接口试了，不能用

官方 CookBook 给的格式是 `<ref>目标描述</ref>` + `\boxed{[x1,y1,x2,y2]}`（0–1000 归一化）。
实测 Ollama 版输出形如 `red circular marker on white paper 468 390 518 445`：

| 图 | 预测框中心（换算成像素） | 真实位置 | 误差 |
|---|---|---|---|
| test2 | (841, 534) | (879, 770) | **y 偏 236 px** |
| test3 | (963, 491) | (882, 692) | **y 偏 200 px** |

而且**负样本（neg3 夜景）它也给了一个框**。
⇒ **grounding 只能当"有没有这个概念"，不能当定位。**

### 8.7 最终链路 v3（8/8）

```
CV: 红度 R−max(G,B)>40
  → 连通域，面积 80 ~ 3%图
  → 圆度 4πA/P² ≥ 0.6
  → ★ 环形带(1.5~2.6r) 打分 score = V̄ − 1.5·S̄ ≥ 100 且 V̄ ≥ 150
  → 无候选 ⇒ 直接判"无"（0 次 VLM 调用，省 6 秒）
VLM: 裁 2.2×直径 → 384px → "A 标记 / B 其他红色物体"，任一个 A ⇒ 有
```

结果：

| 图 | 候选通过 CV | VLM | 预测 |
|---|---|---|---|
| test1 | 0 | — | 无 ✓ |
| test2 | 1（真点） | A | 有 ✓ |
| test3 | 3（含真点） | A,A | 有 ✓ |
| neg1–5 | 0 | — | 无 ✓ |

**8/8，且负样本一次 VLM 都没调用。**

### 8.8 但必须记住三个"不成立"的地方

1. **CV 单独也 8/8**（只要"有候选就算有"）⇒ 在这个测试集上 **VLM 没有增量**。
2. **test3 是靠另外两个白底红磁钉判对的**，不是真点 ⇒ 运气成分。
3. 阈值（score≥100、V̄≥150）是**在 8 张图上调的**，有**过拟合**风险。

⇒ 要证明 VLM 有用，需要一批 **"红点在玻璃上、周围没有白纸"** 的真实数据。
（当晚补测：在夜景楼/天花板/桌面/树丛上贴 30 px 红点，CV 定位正确时 VLM 判 A=4/4，选到叶子时判 B ⟶ VLM 更像"最后一道保险"而不是主力。）
