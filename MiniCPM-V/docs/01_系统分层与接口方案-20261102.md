# 系统分层与接口方案（MiniCPM-V 侧）

> 日期：2026-11-02 ｜ 作者：黄圣鑫 ｜ 状态：讨论稿，待与师兄/文豪对齐
>
> 本文回答一个问题：**MiniCPM-V 在这条链路里到底插在哪、交什么、什么时候退出来。**

---

## 0. 结论摘要（先看这五句）

1. **远、中、近是三件不同的事**，不能用一套方法从头做到尾。
2. **MiniCPM-V 的有效工作区间是 20–25 m**（红点 12–16 px，刚好 1 个 patch），
   再远它只能做**场景级判断**（这是栋楼吗、几扇窗、朝向哪），做不了"找红点"。
3. **8 m 以内必须交给文豪的 CV**——这是他单帧筛选的硬边界（1.5–8 m），不是商量出来的。
4. 我们的程序在文豪状态机前面，叫 **SEEK 段**：
   `SEEK（我）→ ACQUIRE（他）→ ALIGN → DASH`。
5. **最大的风险不在模型，在定位**：飞机凭什么飞到 100 m 外的楼前？VINS 在室外会漂。

---

## 1. 依据：像素预算（不是估的，是用标定值算的）

相机标定（`stereo_calib.yaml`，1920×1080）：**fx = 1579.46，fy = 1583.67**。

```
红点在图上占多少像素 = 1579 × 标记直径(0.20 m) ÷ 距离(m)
视觉编码器的 patch = 14 px（小于 1 个 patch ≈ 模型"意识不到"有个东西）
```

| 距离 | 红点像素 | = 几个 patch | 谁负责 | 能干什么 |
|---|---|---|---|---|
| 200 m | 1.6 | 0.11 | — | 什么都干不了 |
| **100 m** | **3.2** | 0.23 | VLM（场景） | 只认楼、层数、窗户、朝向 |
| **50 m** | **6.3** | 0.45 | VLM（场景） | 同上，能分辨"某扇窗有异色块" |
| **25 m** | **12.6** | 0.90 | **VLM（候选）** | 裁一块问"这是标记吗"——**临界** |
| **20 m** | **15.8** | 1.13 | **VLM（候选）** | 同上，可用 |
| 15 m | 21.1 | 1.50 | 文豪 CV | 红点定位够用了 |
| 10 m | 31.6 | 2.26 | 文豪 CV | 定位 + 锁定 |
| **8 m** | **39.5** | 2.82 | 文豪 CV | **他的单帧筛选下限** |
| 5 m | 63.2 | 4.51 | 文豪 | ACQUIRE 粗估 |
| 3.5 m | 90.2 | 6.44 | 文豪 | 双目角点平面（最准） |
| 1.5 m | 210.5 | 15.0 | 文豪 | 终点附近 |

> **100 m 处 1 像素 = 6.3 cm。** 所以"100 m 找红点"这件事，不是模型不够大，
> 是**光学上就没有信息**。换 70B 模型也一样。

## 2. 四段式分工

```
 ┌──────────────────────────────────────────────────────────────┐
 │  SEEK-A  远距场景级        50 – 100 m                        │
 │  输入：一张 1080p 原图                                       │
 │  CV ：把所有红色候选列出来（3 px 也能找，不负责判断）         │
 │  VLM：①这是建筑立面吗 ②有几层/几扇窗 ③朝向偏多少             │
 │  输出：候选列表 + 场景描述（文字）                            │
 └───────────────────────────┬──────────────────────────────────┘
                             │ 飞到 25 m（停-看-走，每次 6–10 s）
                             ▼
 ┌──────────────────────────────────────────────────────────────┐
 │  SEEK-B  中距候选级        20 – 25 m                         │
 │  输入：CV 裁出的 300×300 候选块（红点在里面 60–200 px）       │
 │  VLM：这个是"窗玻璃上的红色圆标记" / "红砖" / "招牌" / "尾灯" │
 │  输出：候选编号 + 判定 + 置信度 + 画面区域（左/中/右，上/下） │
 └───────────────────────────┬──────────────────────────────────┘
                             │ 飞向被确认的窗，直到 10 m
                             ▼
 ┌──────────────────────────────────────────────────────────────┐
 │  ACQUIRE / ALIGN / DASH     ≤ 8 m                            │
 │  文豪的 stage12_gate.py 全权接管（他的单帧筛选要求 1.5–8 m）  │
 └──────────────────────────────────────────────────────────────┘
```

### 为什么 8–20 m 这段可能谁都不干

文豪的流程要求"看得到整个环"才锁得准（最小助跑 2.8 m、起跑点 3.06–4.0 m），
而在 20–8 m 之间红点已经有 16–40 px，**他的红点检测（R−max(G,B)>40 + 圆度 + 白底）完全够用**。

> 所以更省事的做法可能是：**VLM 只干到 25 m 就撤**，8–25 m 直接给他的 CV。
> 这一条要跟文豪确认——他愿不愿意从 20 m 就开始找红点（而不是等飞到 8 m）。

---

## 3. 与文豪状态机的接口

他现有状态机（说明书第 5 章）：`manual → wait(找环) → align(摆位) → align(对正锁定) → commit → dash → hold → land`

我们不改他的结构，只在最前面加一段：

```
  manual ──T──► SEEK（新增，我们）──► wait(ACQUIRE) ──► ... ──► dash
                  │
                  └─ 超时/失败 ──► 回 manual
```

**交接时需要交出去的东西**（这就是我们的输出定义）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `target_world` | [x, y, z] | 目标所在的**世界坐标**（VINS ENU） |
| `confidence` | 0–1 | 我们对这个目标的置信度 |
| `n_candidates` | int | 画面里一共几个红色候选 |
| `scene_text` | str | 一句话场景描述（给人看的，不进控制） |
| `t_capture` | 时间戳 | 拍这张照片的时刻（不是处理完的时刻！） |

**注意 `t_capture`**：文豪的 `vision_bridge.py` 已经按拍摄时刻插值位姿了，我们要沿用同一个约定，否则位置会对不上。

---

## 4. 交接协议（必须写死，不能靠默契）

| # | 项 | 我们的建议值 |
|---|---|---|
| 1 | **交接条件** | 距离 ≤ 10 m **且** 连续 3 帧判定为标记 **且** 置信度 ≥ 0.7 |
| 2 | **控制权** | 用令牌；同一时刻只允许一套程序发 `/mavros/setpoint_raw/local` |
| 3 | **超时回收** | 我方 2 s 无心跳（或异常退出）⇒ 自动停止发设定点，飞机进入悬停 |
| 4 | **失败回退** | 判定不了 ⇒ 原地悬停 3 s ⇒ 后退 3 m 重拍 ⇒ 连续 2 次失败 ⇒ 交人工 |

⚠️ 血的教训：飞机上**两套程序同时发 setpoint 会打架**——之前 `geometric_controller`
抢设定点，飞机 12 秒没离地（`err_z=+1.50`，`[takeoff] TIMEOUT without liftoff dz=-0.03`）。
所以第 2 条不是形式主义。

---

## 5. VLM 的输入输出规约（关键：把它的嘴管住）

**不要让它自由发挥。** 每个问题都必须是**闭集**，否则没法判对错，也没法算准确率。

| 问题 | 允许的答案 | 用途 |
|---|---|---|
| 这是不是建筑立面？ | 是 / 不是 / 不确定 | 关卡 |
| 画面里大约有几扇窗？ | 0 / 1–3 / 4–10 / >10 | 场景 |
| 这个红色物体是什么？ | 玻璃上的圆标记 / 红砖或墙面 / 招牌或广告 / 车灯 / 其他 / 不确定 | 核心判定 |
| 它在画面的哪个区域？ | 左上 / 上 / 右上 / 左 / 中 / 右 / 左下 / 下 / 右下 | 换算成方向 |
| 有没有遮挡或反光影响判断？ | 有 / 没有 | 质量门控 |

**"区域"怎么变成动作**（这一步在代码里做，不让模型做）：

```
"右下" → 向右偏航 + 降低高度     （水平/垂直各拆一维）
"中"   → 保持方向，只前进
```

> 好处：模型只输出 2–4 个字，decode 从 0.2 s 降到 0.1 s，而且答案可以数对错。

## 6. 延迟预算与节奏

**实测（本机 GTX 1650 4 GB，1B Q4）**：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| load（冷启） | 6–7 s | 只在第一次 |
| **prefill（看图）** | **6.1 s** | 占 93%，701 个视觉 token |
| decode（写字） | 0.1–0.2 s | 答 18 个 token 时 |
| **单次总计（热态）** | **6.0–6.5 s** | |

所以：

| 事项 | 数值 |
|---|---|
| 一次"看图" | 6.5 s |
| 飞机 1 m/s 时，这 6.5 s 飞出去 | **6.5 m** |
| ⇒ 只能"停-看-走"，不能连续引导 | |
| 从 100 m 到 25 m（75 m），每次飞 5 m | **约 15 次 ≈ 100 s**，加 15 次看图 ≈ 再加 100 s |

**结论：整个 SEEK 段大概 3–4 分钟。** 这个量级可以接受（人手动飞也更慢）。

> ⚠️ 别为了快而缩图：1706→700 宽能让 6 s 降到 2 s，
> 但 test2 里 53 px 的红点会缩成 22 px，模型直接从"有"变成"没有"。**省时间 = 丢目标。**

## 7. 风险清单

| 级别 | 风险 | 说明 | 谁能解 |
|---|---|---|---|
| **P0** | **100 m 外靠什么定位** | 现在是 VINS（室内近距离方案），室外对着天空/玻璃幕墙会漂会丢 | 需要 GPS/RTK，或"人飞到附近再交接" |
| **P0** | 100 m 处红点只有 3.2 px | 物理限制，无解；只能飞近 / 换长焦 / 放大标记 | 需求方 |
| P1 | VLM 判定不稳 | 同一张图出现过"有…中央偏右"和"没有，但有一个红色圆点"两种回答 | 我们（多次采样 + 投票） |
| P1 | 6 s 延迟 | 不可连续引导 | 设计上接受 |
| P2 | 图传 300 ms+ 延迟 | 照片是"过去的"，要用 t_capture 插值位姿 | 沿用文豪的 vision_bridge |
| P2 | 玻璃反光/逆光 | 会影响 CV 和 VLM 同时失效 | 换时段 / 多角度 |
