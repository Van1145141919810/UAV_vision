# VB09 无人机建筑立面智能巡检与安全验证项目说明

> **版本：** V1.0  
> **编制日期：** 2026-10-30  
> **计划周期：** 2026-10-30 至 2026-11-28（30 个自然日）  
> **团队规模：** 3 名技术人员  
> **文档属性：** 第一阶段研发立项、技术现状梳理与任务分工文件  
> **依据：** 《VB09 穿环打击系统说明》（2026-10-30）、项目需求描述、MiniCPM-V / Jev / Laya 官方资料

## 0. 执行摘要

项目的远期设想涉及无人机对多栋建筑外立面的自主观察、窗口选择以及破窗作业。目前项目采用贴在窗户上的小尺寸红色圆形标记，作为视觉识别和环境理解阶段的实验对象。现有 VB09 系统已在受控场地积累了双目摄像头、近距离视觉定位、位姿融合、飞控通信、任务状态机和安全监控方面的工程基础，但尚不能证明远距离、多建筑环境中的自主巡检能力。

**本文件制定的是30天的非接触式视觉巡检与系统安全验证计划。** 其可交付成果包括视觉模型离线评测、Jev/Laya 状态决策评测、原系统安全诊断、只读数据接口、模拟与经授权的非接触巡检演示。它**不包括**自主撞击、破窗、接触式打击及将视觉识别结果直接接入破坏性动作执行的开发或测试流程。任何此类远期应用须另行进行用途确认、建筑产权或管理方授权、飞行审批、现场隔离、安全评估及专项合规审查。

**30天合理目标：** 形成“可以复现、可以量化、可以追溯”的巡检感知原型，给下一阶段是否投入实景研发提供证据。不得把一次演示成功等同于工程系统可靠。

## 1. 项目背景与应用场景

### 1.1 项目需求

根据现有需求描述：

1. 场景为数层楼高的建筑立面，多层窗户可能包含实验标记。
2. 当前使用略小于 A4 纸内接圆的红色圆形标记，粘贴于经授权的窗户位置，用作视觉测试对象。
3. 无人机的起飞位置距目标建筑约 100 m，场景中最远可能不超过 200 m。**该距离目前被理解为起飞点至建筑的大致距离，是否要求在此距离直接完成识别，仍待确认。**
4. 现场视野可能同时出现多栋建筑，存在复杂背景、非目标建筑、遮挡、反光等因素。
5. 后续可能研究可见光以外的成像手段，但具体波段、物理检测对象、传感器和应用条件尚未定义。
6. 已有 VB09 平台能够在受控近距离场地对穿梭环及其内部标记进行视觉处理和定位。

### 1.2 当前阶段的任务边界

| 类别 | 第一阶段纳入 | 第一阶段不纳入 |
|---|---|---|
| 感知 | 授权图像的建筑立面理解、视觉标记的离线验证、失败案例分析 | 将识别结果转化为实景撞击目标指令 |
| 决策 | 继续观察、人工复核、停止分析等软件状态判断 | 自主选择接触、撞击或破窗动作 |
| 定位 | 原 VB09 位姿与时间戳的只读复现、异常诊断 | 面向撞击精度的轨迹和控制参数优化 |
| 飞行 | 合规、非接触、人工可接管的观察验证 | 建筑接触、穿窗、破窗或无人监督执行 |
| 传感器 | 当前可见光链路的能力评估；不可见光需求论证 | 未明确需求就采购或集成专用致损任务载荷 |

### 1.3 阶段成果应回答的核心问题

- 真实建筑图像在项目指定硬件上能否稳定输入视觉模型？
- 通用视觉语言模型对于此类场景的能力和失败边界是什么？
- Jev/Laya 结构化决策相对普通规则程序是否提供了可测的收益？
- VB09 的传感器、位姿、飞控通信和监控软件中，哪些模块已可靠，哪些尚有异常？
- 多模型部署是否引入新的延迟、通信、资源竞争或安全问题？
- 是否拥有足够可信的实验数据，支持进入下一阶段？

## 2. 原 VB09 系统现状

### 2.1 已有系统组成

原始技术说明显示，VB09 主要由下列模块组成：

| 模块 | 原有实现 | 当前已知能力 | 对本阶段的价值 |
|---|---|---|---|
| 感知硬件 | 1080p USB 双目相机；另有用于 VINS 的机载双目 | 提供同步图像和近距离立体视觉信息 | 可研究图像采集、时间戳与数据链路 |
| 视觉处理 | 地面站视觉程序；颜色、几何及双目识别 | 在特定穿梭环和红点条件下工作 | 可借鉴图像处理、诊断、回放设计 |
| 数据链路 | 图像经桥接上传地面，结果返回机载侧 | 具备机地数据交互和状态发布 | 可复用只读观察通道的工程经验 |
| 定位融合 | VINS-Fusion、历史位姿插值、世界坐标融合 | 受控近距离环境的位姿估计 | 可用于非执行状态的定位质量分析 |
| 飞控系统 | PX4、MAVROS、ROS1 | 具备飞控通信和状态监视 | 作为既有平台的接口基础 |
| 监控与日志 | 网页监控、飞行状态与诊断日志 | 记录原始观测、估计、异常和时间信息 | 为复现测试与安全审计提供证据 |
| 任务软件 | 既有状态机和近距离执行软件 | 依赖人员先将飞机引导到近距离场景 | 仅作边界分析、安全审查；不接入本阶段破坏性执行 |

> 说明：以上为“技术说明文档记载的能力”，不等于本计划编制方已在实机上重新验证。

### 2.2 明确已有的工程成果

1. 已形成可运行的软件分层，包括感知、数据传输、估计、飞控、监控和日志。
2. 已在受控场地形成针对特定环状结构及红色标记的识别与近距离定位链路。
3. 已考虑图像采集时刻与位姿时刻的对应关系。
4. 已设计部分启动前检查、异常监视、人工接管和退出流程。
5. 已有实验日志，可支持进一步诊断和回归测试。

### 2.3 当前未解决或未证实的问题

**P0：现有定位异常。** 原文档第 9.4 节记录过约 8–10 cm 的红点与环心高度估计差异，原因未定；还记录 VINS 高度偶发跳变，幅度约 5–75 cm。这些现象需以原始日志复现、界定发生条件和影响范围，不能直接假定已修复。

**P0：场景迁移未经证明。** 现有演示是近距离、结构化、受控场地；新需求是远距离、多栋建筑、室外背景，存在显著场景差距。

**P0：原视觉算法假设不同。** 穿梭环包含特定颜色带、几何尺寸与标记背景；真实建筑外窗并不天然满足这些条件。

**P0：定位体系差异。** 既有 VINS 使用局部视觉惯性坐标，尚无资料证明其在远距离室外建筑巡检条件下的长期稳定性。

**P1：算力与数据链路。** 机载计算平台、无线图传能力、地面站 GPU、持续运行功耗和端到端延迟仍需核实。

**P1：人工接管与安全处置。** 现有安全设计面向特定试验场地，不能直接视为适用于多建筑室外环境的完整安全论证。

### 2.4 技术成熟度判断

| 能力 | 当前判断 | 判断依据 |
|---|---|---|
| 既有系统启动与近距离实验复现 | 有基础，需复验 | 原 VB09 说明及历史记录 |
| 指定近距离视觉结构的识别 | 有阶段性结果 | 原 VB09 说明 |
| 多建筑场景理解 | 未验证 | 缺少对应数据与测试报告 |
| 远距离微小标记的稳定辨认 | 未验证 | 缺少实际成像和可靠性证据 |
| 室外长距离自主定位 | 未验证 | 现有资料主要覆盖受控近距离情形 |
| Jev/Laya 在本项目状态判断中的收益 | 未验证 | 尚无领域内基线对照 |
| 不可见光传感器选型 | 需求未冻结 | 波段、检测物理量及应用条件未知 |
| 破窗作业的安全和合规验证 | 不在本阶段范围 | 需独立专项评审 |

## 3. 拟评估的技术路线

### 3.1 MiniCPM-V：图像理解候选模块

建议评估 OpenBMB 的 **MiniCPM-V 多模态系列**，而非仅使用 MiniCPM 纯文本模型。视觉语言模型用于理解建筑立面场景、产生人工可核对的场景描述和辅助离线分析。

**必须验证的事项：**

- 指定硬件是否支持选定模型的稳定加载和推理；
- 推理时延、显存与长期稳定性；
- 对复杂建筑外观、遮挡、反射、光照变化的失败情况；
- 输出是否可追溯至原始图片；
- 相比简单视觉基线是否有足够的增益。

**限制：** 图像理解能力不等于精密空间定位能力；模型输出文字也不能代替传感器质量评估或飞行控制约束。

### 3.2 Jev / Laya：有限状态判断候选模块

**Jev** 是 TypeSafe 提供的结构化决策服务，**Laya** 是独立的开源本地决策项目。两者可用于在给定状态下输出候选分类、分数或二元判断。第一阶段允许评价它们对“继续离线观察 / 需要人工复核 / 停止分析”等非执行状态的帮助。

需评估：

1. Jev 云端接口与 Laya 本地接口的可用性；
2. 决策准确率、置信度校准与拒绝判断；
3. 相对普通确定性规则的实际价值；
4. 网络中断、模型超时、异常输入时的软件退化；
5. 输出能否稳定记录与复现。

**基本原则：** 模型不直接控制飞行执行机构；安全关键条件由独立规则验证。若模型相对确定性规则没有可验证收益，不强制在后续采用它。

### 3.3 原 VB09：传感器与安全基础

保留原系统负责人，主要执行：

- 软件、硬件、版本和运行依赖清点；
- 历史日志检索和已知异常复现；
- 只读图像、位姿健康度、通信状态数据接口；
- 非执行模式下的仿真与回放；
- 安全监控、异常记录和人工接管机制审查；
- 明确哪些原有功能不能迁移到新环境。

不将新视觉模型的结果直接连接至原有接触式执行路径。

### 3.4 推荐的安全验证数据流程

**经授权采集的图像 / 记录 → 离线数据管理 → MiniCPM-V 场景理解 → Jev/Laya 状态判断测试 → 规则校验 → 人工复核 → 评测报告和日志。**

在该流程中，模型产生的是可检查的观察和判断数据，不是对窗户接近、撞击或破窗的飞行指令。

### 3.5 不可见光的后续预研

“不可见光”必须先拆分为真实物理需求：希望观测的是表面热分布、材料反射特征，还是某种特殊的非接触识别线索？不同波段所需硬件、光学窗口、成像效果不同。尤其不能把普通热像仪理解为能穿透普通窗玻璃的设备。

在任务需求和合法用途尚未冻结前，本阶段不制定针对窗口破坏性选择的特殊传感器配置。

## 4. 团队组织与责任划分

| 岗位 | 负责人代号 | 主要职责 | 应避免的职责重叠 |
|---|---|---|---|
| 多模态视觉负责人 | A | MiniCPM-V 选型、部署、离线图像测试、推理服务、视觉评估报告 | 不负责飞控与实景动作指令 |
| 结构化决策负责人 | B | Jev/Laya 对比、部署、状态接口、规则对照、异常与置信度测试 | 不直接控制飞行器 |
| 原平台与安全负责人 | C | VB09 系统清点、日志复现、定位健康评估、只读接口、仿真、安全审查 | 不将新模型接入破坏性执行 |

### 4.1 协作原则

- A 提供图像理解服务以及可回放的测试结果。
- B 使用模拟或回放状态进行决策模型评测，不等待 A 完成所有部署才能开始。
- C 提供只读传感器与状态接口、实验记录和安全审查结果。
- 三人共享统一的数据字段、版本记录、失败样例和问题看板。
- 每日进行 15 分钟同步，报告“已完成事项、当日阻碍、下一步、需要他人配合”。
- 每五天执行一次阶段验收，由项目负责人决定是否进入下一阶段。

### 4.2 建议的协作数据字段

| 数据组 | 示例字段 | 目的 |
|---|---|---|
| 图像 | image_id、capture_time、image_path | 确保输入可追溯 |
| 推理记录 | model_name、model_version、result、latency_ms、error | 复现实验 |
| 定位健康 | pose_valid、pose_age_ms、sensor_status | 判断信息是否可用 |
| 系统状态 | link_ok、operator_review_required、fault_code | 软件状态分析 |
| 审核记录 | human_review、review_time、review_note | 人工确认与审计 |

以上为建议性软件接口，实际字段以团队联调确定；这些字段不承担运动控制命令。

**A：**

**B：**

**A：**

#### D4：封装、对照和异常处理

**A：**

- 测试损坏图片、服务超时和重复请求。

**B：**

- 建立简单确定性规则基线；
- 对比 Jev/Laya 的判断与基线；
- 测试低可信、超时和不可用时的停止或人工复核逻辑。

**C：**

- 编写只读数据接口说明；
- 检查日志、监控与人工接管相关的安全状态；
- 形成尚待验证的问题与风险清单。

**当天验收：** 接口可解释、异常有记录、原系统问题不再只停留于口头描述。

#### D5：联合验收

**A 演示：** 在指定硬件上启动 MiniCPM-V，输入未参与调试的测试图像，展示输出、资源占用和成功/失败案例。

**B 演示：** 启动 Jev/Laya 或其中已验证可用的实现，以模拟设备状态展示结构化判断、规则对照及异常处理。

**C 演示：** 原系统架构说明、历史数据回放、定位异常证据、只读接口与安全风险表。

**团队交付：**

1. 三份部署或复现文档；
2. 三套独立测试结果；
3. 一份统一字段的接口草案；
4. 一份 P0/P1 问题清单；
5. 一份 S2 阶段任务修订表。

**D5 退出标准：** 三人的结果都能由另一位成员在相同环境复现；不能复现的条目必须列明阻碍，不宣称已完成。

### 5.2 第二阶段 S2：数据与接口

- **A：** 补充图像数据来源说明、标注规范、数据版本，形成独立训练/验证/测试用途划分；第一期优先离线评测。
- **B：** 完善结构化状态协议，明确合法值、异常值和人工复核逻辑。
- **C：** 提供只读图像、位姿健康度、系统状态样例，确认数据时间戳和来源。
- **阶段验收：** 统一接口能够跑通离线数据，数据集可追溯，模型不能直接触发运动执行。

### 5.3 第三阶段 S3：可靠性与失败评估

- **A：** 统计视觉模型结果，按天气、光照、复杂背景等条件分组分析；保留代表性误判案例。
- **B：** 与确定性规则对照，检查输出置信度是否可信以及何时需要拒绝判断。
- **C：** 复核历史定位异常和关键通信状态，完成非执行条件下的故障复现。
- **阶段验收：** 给出有证据支持的能力边界和失效模式清单，禁止只用最好案例评价整体能力。

### 5.4 第四阶段 S4：非接触巡检软件联调

- **A：** 将图像理解服务连接至测试界面，允许查看原始图像、模型输出、耗时和异常。
- **B：** 完成观察状态、人工复核和巡检记录流程。
- **C：** 完成仿真及必要的安全检查；仅在获得合法场地与飞行授权、满足现场隔离条件时开展非接触式人工观察验证。
- **阶段验收：** 演示具有完整日志的软件闭环，不允许模型绕开人工控制直接命令飞行器接触建筑。

### 5.5 第五阶段 S5：稳定性及安全验证

- **A：** 重复测试、长时间运行、模型崩溃后的服务恢复记录。
- **B：** 网络或模型失效、异常数据、低置信度情况下的软件安全退化验证。
- **C：** 离线/仿真模式下的异常处理和人工接管测试。
- **阶段验收：** 关键异常有记录、有处理路径，未关闭的严重问题会阻止进一步现场试验。

### 5.6 第六阶段 S6：最终验收与复盘

- **A：** 提交模型部署、离线评测、资源消耗、误报漏报和失败样例。
- **B：** 提交 Jev/Laya 适用性、规则基线、置信度和异常处理报告。
- **C：** 提交原系统现状、安全问题与非接触验证记录。
- **项目负责人：** 组织技术评审，决定保留哪一类模型、哪些问题进入下一阶段、哪些需求必须收缩或重定义。

**最终交付：** 一个安全隔离的建筑立面视觉巡检演示原型，以及足以支持下一步投入决策的真实数据证据。

## 6. 交付物与验收标准

### 6.1 人员交付物

| 人员 | 交付物 | 可核验形式 |
|---|---|---|
| A | 环境安装说明、模型配置、推理服务、评测集、性能报告 | 同事可复现推理；含原始样例和完整指标 |
| B | Jev/Laya 测试环境、决策协议、规则基线、异常测试、适用性结论 | 输入输出可回放；能解释与规则不一致之处 |
| C | 原系统架构、版本清单、历史异常证据、数据回放、只读接口、安全审查 | 有日志证据；不会依赖危险动作演示 |
| 团队 | 30天总结报告、演示视频、风险清单、下一阶段决策 | 评审会上逐项复核 |

### 6.2 建议统计的指标

**视觉：** 识别结果与人工标注的一致性、误报率、漏报率、不同场景条件下的分层表现、推理耗时分布、模型加载时间和资源占用。

**决策：** 分类准确率、错误时的置信度、人工复核触发率、与规则基线的一致性、响应时间、接口异常率。

**系统：** 数据丢失率、日志完整性、时间戳可追溯性、服务异常恢复情况、位姿健康状态、人工接管与安全监控的测试结果。

**安全：** 模型输出与飞控执行隔离、关键故障下自动分析停止、操作员随时可中止、现场授权和隔离措施有证据。

**注意：** 本项目尚无可审计基线，不应凭空承诺“识别率 95%”或“定位误差小于某值”。D10–D15 获取数据后，才为本阶段的非接触任务制定合理通过门槛。

### 6.3 五个里程碑决策门

1. **D5：部署门。** 模型是否能运行，原系统是否有可复现诊断基线？
2. **D10：数据门。** 测试数据是否足够清晰、合法且有一致标注？
3. **D15：能力门。** 模型是否有独立实测价值，哪些情况容易失败？
4. **D20：集成门。** 软件数据流是否完整且与危险执行行为隔离？
5. **D30：验收门。** 是否具备进入下一期非接触自主巡检研究的条件？

## 9. 项目启动前必须确认的条件

以下项目需求信息尚未确定，会显著影响实际工作量：

1. **硬件：** 原 VB09 机载计算设备是否仍是 Khadas？是否另有地面 GPU？两端的系统与资源规格是什么？
2. **100–200 m 定义：** 是起飞点至建筑的地理距离，还是要求在该距离完成图像观察与识别？
3. **摄像头：** 原有双目相机是否仍用作阶段测试设备？有没有其他非接触观察传感器？
4. **模型部署：** 最终更倾向 Jev 云端 API，还是 Laya 的本地运行？是否有离线运行要求？
5. **数据：** 是否已有经过授权的多建筑立面图像？是否允许团队建立匿名、非敏感的离线评测集？
6. **场地与安全：** 是否已有合法试飞场地、建筑方许可、安全员和现场隔离条件？
7. **验收方式：** 第30天要求的是研究报告、软件现场演示，还是实际非接触巡检演示？不同定义的工作量差别很大。

在上述条件得到确认之前，本文的30天计划为**基于当前信息的基线计划**，而非对最终应用功能的交付承诺。

## 10. 项目阶段结论与下一步

**第一，原有 VB09 系统有工程积累，但其主要证据来自受控近距离场景，不能直接外推为多栋建筑远距离自主能力。**

**第二，MiniCPM-V 可以作为图像理解候选，但模型名称或公开基准分数并不能替代本项目图像数据验证。**

**第三，Jev/Laya 只应在确实优于确定性规则、且有可靠故障处理时保留。** 30天中不应让第二名人员只做模型安装而忽略领域内测试。

**第四，C 应保留对原系统的连续维护责任，但当前优先级是排除未解释的定位与安全问题，形成可以复现的技术证据。**

**第五，首期交付的价值在于可信验证，而不是宣称已具备窗口撞击或破窗能力。** 一旦 D15 的数据不能证明可见光观察方案有效，就应调整任务范围和传感器研究路径，而不是继续叠加复杂模型。
