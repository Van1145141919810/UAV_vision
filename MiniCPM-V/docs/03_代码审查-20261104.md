## 二、发现并修复的问题

### 1. `cli.py` 单张图会**跑两遍模型**（真 bug）

```python
# 改前
res = detect(p, ...)        # 第一次
if args.json: print(...)
else: run_one(p, ...)       # run_one 内部又 detect 一次 → 第二次
```

**后果**：不加 `--json` 时，同一张图调用两轮 VLM，白花 6 秒。
**修复**：统一走 `_one()`，检测一次、按需输出。实测 `elapsed_s` 从 ~7s 降到 0.73s。

### 2. `cli.py` 模型没起时会**抛异常栈**

`detect()` 里的 `VLMError` 没人接，用户看到一屏 traceback。
**修复**：捕获后提示「加 `--no-vlm` 只跑 CV，或先启动 Ollama」。

### 3. `demo_click.py` 红点框坐标解包错（已在前一版修）

`dot_boxes` 存 `(x, y, w, h)`，渲染却按 `(x0, y0, x1, y1)` 解包，
框会从候选点一路拉到 `(宽, 高)`，变成横跨半屏的巨框。
**修复**：按 `(x, y, w, h)` 解，画到 `(x+w, y+h)`。

### 4. 红点精确模式取错了候选（已在前一版修）

`arm()` 里写死 `self.dot_cands[0]`，选中的不是第一个时距离会按错的直径算。
**修复**：按选中点找最近的候选。

## 四、遗留风险（今晚必读）

| # | 风险 | 影响 | 现在怎么防 |
|---|---|---|---|
| **R1** | **`COM_OBL_ACT` 不是 0** | 程序停发设定点后飞机**自己降落** | 上机第一件事读这个参数；不是 0 就别飞 |
| R2 | 别人也在发 `/mavros/setpoint_raw/local` | 两边打架，飞机不动或乱动 | 启动前 `rosnode list` + 查 topic 发布者 |
| R3 | 相机安装角 `CAM_PITCH_DOWN_DEG=5.23` 是**抄文档的** | 瞄准会系统性偏一个固定角度 | 实飞时看"每次都往同一侧偏"就说明要重标 |
| R4 | 窗宽 2.0 m 是假设 | 估距整体偏 ±25% | 已知；远距不靠米数，只做参考 |
| R5 | `on_window` 判定不可靠（3 例错 1） | 只影响 JSON 字段，不卡流程 | `REQUIRE_ON_WINDOW=False` |
| R6 | VLM 反光判定恒为"有" | JSON 字段可能失真 | 只记录，不做判据 |

## 五、今晚桌面验证清单（拆桨后，不飞）

按顺序做，任何一步不过就停：

| # | 检查 | 命令 / 看什么 | 通过标准 |
|---|---|---|---|
| 1 | 飞机能连 | `ssh visbot@192.168.2.20` | 能登录 |
| 2 | ROS 起来 | `rosnode list` | 有 mavros、vins |
| 3 | 位姿正常 | `rostopic hz /mavros/local_position/pose` | ≥ 15 Hz |
| 4 | **谁会抢设定点** | `rostopic info /mavros/setpoint_raw/local` | 发布者只有预期的一个 |
| 5 | **`COM_OBL_ACT`** | `rosservice call /mavros/param/pull` 后读 | **必须是 0**（悬停） |
| 6 | 相机出图 | `rostopic hz /det_cam/image_raw` | ≥ 8 Hz |
| 7 | 笔记本能拿到图 | 一次 SSH 抓帧 | 存下来能打开 |
| 8 | 点击算指令 | `run_click.cmd` 点一扇窗 | 显示"前 X 米 下 Y 米" |
| 9 | 指令落盘 | 回车 | `data/results/` 出现 `record_*.json` |

**第 5 条是今晚最关键的**：`COM_OBL_ACT=2` 时，程序一退出飞机就会自己往下掉。
